# Orca 0.32.0

Second performance release. 0.31.0 fixed the pre-passes and the streaming session; this one
fixes the tree mapper, which turned out to be where the remaining overhead actually was, and
closes the last shape that could take the parser down.

## Highlights

- **Inline mapping is ~7x faster.** The combined `++underline++` / `^sup^` / `~sub~` /
  `==highlight==` pattern was compiled from scratch **for every text node**, and running it
  costs about as much as building it. The admonition pattern was rebuilt per blockquote and
  the code-span pattern per code span. All three are now compiled once, and every inline
  rewrite pass (footnotes, math, emoji, decorations, text merging) first checks whether it
  can possibly apply before rebuilding the list.
  Tree mapping of a 1.3 MB document: **366 ms → 49 ms**. Full parse: **488 ms → 172 ms**.
  Orca's cost on top of the upstream parser: **5.0x → 1.8x**.
- **Block nesting guard.** The block parser recurses once per quote marker and per list
  level, and its cost grows far faster than the source: 512 nested list levels took 100 ms,
  2 048 took 5 s, 4 096 never finished, and 25 600 quote markers exhausted memory or the
  stack depending on stack size — all before any AST depth limit was reached.
  `maxBlockNestingDepth` (default 128) keeps such a block as a plain text paragraph and
  reports it. `>` × 25 600: **→ 33 ms**. 4 096 nested list levels: **→ 137 ms**.
- **Benchmarks normalise by bytes.** Scaling checks now compare cost *per byte*, so shapes
  whose byte count grows faster than the generator's parameter (nesting, for one) are
  measured correctly instead of failing for the wrong reason. The limit tightened from 7.0x
  to 1.75x, and the suite gained nesting cases plus an Orca-versus-upstream overhead check.

## What did *not* change

AST output. The mapper rewrite was verified with a golden diff over 8 real markdown files
(README, all `docs/`) and 20 synthetic documents covering every inline and block feature,
CRLF, front matter, and the awkward `$`/`^`/`~` cases: 235 KB of dump, byte-identical before
and after.

## API

```kotlin
OrcaMarkdownParser(
    // …
    maxBlockNestingDepth = 128, // quote/list nesting per block before it is kept as plain text
)

OrcaParseWarning.BlockNestingLimitExceeded(
    maxBlockNestingDepth = 128,
    exceededDepth = 25_600,
    guardedBlocks = 1,
)
```

The guard never counts indented code or fenced content, and it does not touch `maxTreeDepth`:
a document that nests deeply but stays under the guard still produces a truncated tree with
`DepthLimitExceeded`, exactly as before.

`OrcaMarkdownParser` gained a trailing parameter and `OrcaParseWarning` a variant; source
compatible, not binary compatible with 0.31.0.

## Measurements

Warm JVM, minimum of several runs.

| case | 0.31.0 | 0.32.0 |
|---|---:|---:|
| tree mapping, 1.3 MB document | 366 ms | 49 ms |
| full parse, 1.3 MB document | 488 ms | 172 ms |
| overhead over the upstream parser | 5.0x | 1.8x |
| `>` × 25 600 | OOM / stack overflow | 33 ms |
| 4 096 nested list levels | > 20 s | 137 ms |
| 512 nested list levels | 101 ms | 44 ms |
